How the AutoNgoaLong bot sees, decides and clicks

The bot drives the Flash game Ngọa Long inside the Coowon browser without taking over the mouse. It captures the window in the background, finds the 1000×600 game canvas on every frame, names the screen from template signatures, and posts clicks to canvas-relative offsets. Every wait has a time limit and every step can be stopped.

Big picture

Five layers, one direction of dependency

The UI only talks to the engine; features only talk to RunContext; the core never imports the engine. Game knowledge (offsets, scenes, templates) lives in profiles/ngoalongviet/ and can be edited without rebuilding. Click any module for its job and files.

Life cycle

From double-click to a saved run

Startup builds one AppServices object that wires everything together. Pressing Bắt đầu creates a fresh RunContext and hands the feature to a worker thread. Step through the stages.

    TaskRunner · RunControl

    Run states: Start, Pause, Stop

    Each game window has its own TaskRunner, a QThread with four states. Stop and Pause are two threading.Event flags in RunControl. The task notices them at its next checkpoint: every click, every poll and every 50 ms slice of a sleep. Try the buttons.

    Hotkeys: Ctrl+Alt+F10 stops every runner, the pause hotkey toggles all of them, Ctrl+Alt+D toggles debug mode. Bare F-keys are refused.

    Signals the UI receives

    Signals are emitted from the worker thread and Qt queues them onto the UI thread, so the window never freezes during a run.

    engine/context.py · RunContext

    Waiting and clicking

    Features never sleep blindly and never use screen pixels. They wait for a template or a scene with a time limit, and they click canvas-relative keys that are converted with the current canvas origin and scale.

    ctx.wait_for(name, timeout_s): the polling loop

    Each poll calls observe() (fresh capture, canvas, pop-ups), searches every wanted template, records a Detection, then sleeps poll_interval_s (0.25 s). Move the sliders to see how a wait ends.

    From a coords key to a Windows message

    Offsets in profiles/ngoalongviet/coords/*.yaml are measured on a 1000×600 canvas. CanvasFix.to_frame() turns them into client pixels: origin + offset × scale. Page zoom only changes scale, so nothing has to be re-recorded.

    
        
    Win32InputDriver.click() posts these messages to the top-level Chrome_WidgetWin_1 window. Coowon has no render-widget child, so client coordinates go straight to the browser window and the real cursor never moves.

    engine/runner.py · engine/scheduler.py
    
      
    How a run ends, and what happens next
    
      
    execute(task, ctx) never raises. It collapses panels, calls task.run(ctx), maps the outcome to a RunResult, and always calls task.on_stop(ctx).
    
      
    
        
    DONE
    run() returned. Its string becomes the log line “Xong: …”. Default message: “Hoàn thành”.
    
        
    STOPPED
    Cancelled (user pressed Stop) or TaskStopped (the bot chose to stop, for example a declined gold-cost pop-up).
    
        
    FAILED
    Any other exception: WaitTimeout, SceneTimeout, CanvasNotFound, WindowGoneError… The last frame is always saved as a failure PNG.
    
      
    
      
    
        
    
          
    After every run
    
          
      
            
    • RunResult carries status, message, duration, counters (clicks, spins, popups, progress…) and the failure screenshot.
      • 
            
    • The run history stores it under data/ (“Lịch sử” tab).
      • 
            
    • The notifier sends tray, Telegram or Discord messages, with a screenshot cropped to the canvas when it is reliable.
      • 
            
    • logs/run-<id>/run.log keeps every log line, plus step PNGs in debug mode.
      • 
          
    
        
    
        
    
          
    Routines (“Chuỗi tác vụ”)
    
          
    A routine is a saved list of feature steps with times of day and weekdays, stored in data/routines.json. SchedulerService ticks every 15 s; a missed slot still runs within a 5-minute grace window.
    
          
      
            
    • FAILED step: retried up to retries times after retry_delay_s; then skipped, or the routine ends if stop_on_error.
      • 
            
    • STOPPED step: the whole routine stops.
      • 
            
    • Steps that loop until Stop (Thám Bảo, Võ Khôi Tháp, AutoClick with 0 rounds) need max_duration_s; when it runs out the step counts as done.
      •

    debug/ · tests/ · selftest.py
    
      
    Debugging and testing without the game
    
      
    
        
    
          
    One DebugFrame, three outputs
    
          
    Every find, wait_for and expect_scene records a Detection (name, rectangle, score, threshold, found). Together with the canvas, scene and planned clicks they form a DebugFrame, drawn by:
    
          
      
            
    • Live overlay: a click-through, top-most Qt window glued over the game.
      • 
            
    • Debug panel in the app, so it works while the game is covered.
      • 
            
    • PNG files logs/run-<id>/NNN-<step>.png in debug mode; a failure frame is saved in every mode.
      • 
          
    
          
    Switch on with --debug, the checkbox, or Ctrl+Alt+D.
    
        
    
        
    
          
    Offline replay
    
          
      
            
    • FileCapturer replays stored screenshots instead of a live window; RecordingInputDriver records clicks instead of posting them.
      • 
            
    • Golden tests check the canvas rectangle (±2 px) and the scene name for every screenshot in tests/fixtures/screens/expected.yaml.
      • 
            
    • python -m ngoalong --selftest checks the profile, features, 15 golden screenshots and the main window, exit code 0 or 1.
      • 
            
    • Live tests run only with NGOALONG_LIVE=1 and an open game window.

    Extension points
    
      
    Adding a feature
    
      
    
        
      
          
    1. Capture the screens. Use the “Mẫu ảnh” tab: drag a rectangle on a live capture, test its score, save. Each save writes the PNG, a template_crops.yaml line and a scene entry.
      2. 
          
    2. Describe the screens in scenes/<area>.yaml: a signature that must all match, and the objects to click.
      3. 
          
    3. Add fixed offsets to coords/<feature>.yaml for anything clicked by position.
      4. 
          
    4. Write features/<feature>.py with @register, a Params model and run(ctx). Only use ctx; no sleeps, no screen pixels.
      5. 
          
    5. Test offline with stored screenshots through FileCapturer and add them to the golden set.
      6. 
        
    

    @register
class MyFeature(Task):
    id = "my_feature"          # settings key, coords file
    title = "Tính năng mới"     # shown in the UI
    order = 120
    Params = MyParams
    start_scene = "city"

    def run(self, ctx: RunContext) -> str:
        ctx.expect_scene("city", 5)
        ctx.click("my_feature.open")
        ctx.expect_scene("my.dialog", 5)
        ctx.click_object("my.dialog", "ok")
        return "Xong"
